# ADR-005：不可变账本、补偿事件与库存物化

- 状态：accepted
- 日期：2026-07-14
- 责任角色：后端负责人、产品负责人
- 产品复核门禁：Stage 5 前确认跨日 return UX

## 决策

账本动作仅为 `take`、`return`、`retire`。已接受事件只追加，不允许 PATCH、普通 DELETE 或原地改写；纠错通过新补偿事件完成。

- `take`：库存至少为 1，事件追加与库存减 1 同事务。
- `return`：通过 `reversesEventId` 关联同用户、同资产且仍有可返数量的 `take`；事件追加与库存加回同事务。
- `retire`：记录退役数量并将对应资产库存归零；多资产操作用 `batchId` 聚合，不用默认资产代替其他资产。
- 库存是账本驱动的物化状态，外部 API 禁止直接改库存。

事件保存品牌、焦油、单位成本、健康折算、风险快照和 `modelVersion`，避免资产资料/算法变化重写历史。

## 未决产品点

跨本地自然日 return 是允许正常撤销还是进入纠错流程，由产品负责人在 Stage 5 前确认；无论选择如何，都不能造成净取出或库存为负。

## 验证

并发 take、重复 return、乱序 return、retire 与 take 竞争、事务回滚和重放必须有真实 PostgreSQL 集成测试。
