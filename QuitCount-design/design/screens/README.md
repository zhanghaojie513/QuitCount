# design/screens · 定稿切图（37 张）

本目录是**当前定稿的 27 屏切图**，由 `../prototype-visual/`（已全量按模型 A1 校准的可点原型）
程序化导出，**不是**从 Ardot 画布导出。

> **规格**：786 × 1704 px = **393 × 852 逻辑像素的 @2x**。与上一版切图（`screens-v1/`，已删除）尺寸一致，
> 可直接替换，不影响任何引用切图尺寸的下游。

## 与旧版（`screens-v1/`）的关系

旧目录是**美化版第一版的 21 张切图**（只覆盖 `01`–`21`，缺 `22`–`27`），导出于多项拍板之前，
与 `design-spec.md` 有 3 处实质冲突。该目录及其备份**均已删除**。

**本目录是它的替代品，且已修掉全部 3 处冲突** —— 见下方「旧缺陷核对」。

## 为什么从原型导出，而不是从画布

画布（Ardot）**尚未同步**到 27 屏的定稿状态。`prototype-visual/` 则是已全量按 A1 口径校准、
并通过 151 项断言的**唯一可信视觉源**。在画布同步之前，从它导出是唯一能保证切图与规格一致的做法。

> ⚠️ **权威顺序不变**：`../design-spec.md`（口径）> `../design-full.html`（逐屏规格）> 本目录切图。
> 切图是**产物**，冲突时以上面两者为准。

## 命名规则

```
NN-屏名.png                     单态屏
NN-屏名-状态名.png              多态屏，每个状态一张
```

`NN` 为两位屏号，与 `design-full.html` / `prototype-visual` 的编号一致。

## 重导方法（可复跑）

```bash
cd ../prototype-visual
python qa/make-export-page.py     # 生成 _export.html（抹掉模拟器外壳，只留 393×852 屏本体）
python qa/export-screens.py       # 逐屏导出 37 张 → design/screens/
```

> `_export.html` 是**中转页，不入库**（已写进 `QuitCount-design/.gitignore`）——
> 它在跑 `make-export-page.py` 时自动重生，所以**找不到它是正常的**，不要手工补一个。
> 新克隆仓库后要出图，直接跑上面两条命令即可。

脚本会**自动读取 `screens.js` 的屏清单与状态数**，所以后续屏数或状态增减时，
重跑即可，不必手工维护清单。

> **用 `grep` 数屏会被注释骗**：`screens.js` 的注释里有 `screen({id:'s23', ...})` 这样的示例文字，
> `grep -c 'screen({'` 会数出 28。**要拿权威数字，跑一次 Node**：
>
> ```bash
> node -e "const fs=require('fs'),vm=require('vm');const sb={window:{},document:{addEventListener(){}}};
> vm.createContext(sb);vm.runInContext(fs.readFileSync('screens.js','utf8'),sb);
> const S=vm.runInContext('SCREENS',sb),V=vm.runInContext('VARIANTS',sb);
> console.log(S.length, new Set(S.map(s=>s.id)).size, JSON.stringify(Object.fromEntries(Object.entries(V).map(([k,v])=>[k,v.length]))))"
> ```
>
> 当前结果：`27 27 {"s01":5,"s02":4,"s08":2,"s25":3}` → 切图张数 `27 + 4 + 3 + 1 + 2 = 37`。

## 什么时候需要重导

- `prototype-visual/` 的视觉有改动（改了 `screens.js` / `style.css`）→ 重跑导出
- 画布同步完成后 → 可改为从画布导出，并以本目录作为**对照基准**验证一致性
